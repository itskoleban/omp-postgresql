# Package procedure

The existing CI x86 jobs build once, run the core and server tests, stage the CMake
`omp-postgresql` installation component and assemble a deterministic ZIP. No x64 server
packages are advertised. `workflow_dispatch` also permits a manual build after the workflow
is integrated into the default branch. Repository permissions remain `contents: read`.

`scripts/package.py create` requires a clean tracked checkout without any untracked installation
assets, including files ignored by Git. Ignored private documents or examples in `docs/`,
`examples/`, `pawn/` or `scripts/patches/` are rejected before CMake staging; build inputs
outside those installation directories remain allowed. It also requires a Release build whose
generated metadata matches HEAD, the expected x86 binary and explicit libpq/license
paths. It inspects every included PE/ELF runtime, rejects unexpected dependency imports,
and includes only required non-system Windows DLLs. Linux distributes libpq alone;
system loader dependencies and symbol-version requirements are inventoried. Staging
starts in a new temporary directory; developer files, logs and credentials are never
copied by a recursive repository sweep.
Documentation include links are adjusted to the installed `qawno/include` location;
all relative Markdown links are checked against the payload before packaging/extraction.

The CMake target and installation component remain `omp-postgresql`; the target's
`OUTPUT_NAME` is `PostgreSQL`. Its existing empty `PREFIX` produces `PostgreSQL.so`
on Linux and `PostgreSQL.dll` on Windows. Packages install that one platform binary in
`components/` and the public include as `qawno/include/omp_postgresql.inc`. Include usage is
`#include <omp_postgresql>` after `#include <open.mp>`. The project name, internal component
identity, UID and version semantics are unchanged; see [RC migration](installation.md#migrating-from-previous-release-candidates).

The archive name remains `omp-postgresql-0.1.0-rc.2.COMMIT-PLATFORM-x86.zip`, where
`COMMIT` is the first twelve characters of the exact source SHA and `PLATFORM` is
`windows` or `linux`. The source archive uses the same version/commit identity with
the suffix `-source.zip`. The naming change does not prepare a new release. Published RC.1, RC.2 and
`0.1.0-experimental.COMMIT` packages remain verifiable and are never relabelled. Each contains a
single `omp-postgresql/` directory, public include, component, docs, examples, legal
notices, selected runtime files and `manifest.json`. The manifest records full commit,
Release configuration, compiler, libpq header version, pinned SDK/Pawn revisions and
SHA-256 of each payload file. External Windows CRT and Linux system libraries are listed
explicitly. Their absence from the archive is deliberate.

Windows assembly additionally requires the `libpq-build-info.json` generated by
`package.py record-libpq` immediately after the patched dependency build. The manifest's
`libpq_build` records its source version, exact DLL hash and mutex-patch hash. Verification
matches those against the DLL, packaged patch and CMake libpq header version. This binds
the build record to the distributed bytes; it is not a signed supply-chain attestation.
The patch and rationale are mandatory payload files on both systems; Linux does not apply
the Windows correction. Source builds and external Windows clients require the review
described in [the Windows build guide](build-windows.md).

ZIP entries are sorted, timestamps use the source commit time (UTC), permissions are
normalized and compression is fixed. Two assemblies with identical inputs must have
identical SHA-256; this is checked before upload. Compiler/toolchain updates can still
change input binary bytes. The procedure does not claim hermetic reproducible compilation.

`scripts/package.py verify` checks the archive's checksum, safe paths, no duplicate/symlink
entries, exact payload inventory, required files, hashes, binary architecture and version/
commit/name consistency **before** extraction into a previously nonexistent directory.
The x86 jobs compile all examples using the extracted include, unpack a fresh official
open.mp server, clear development DLL/loader search paths, and rerun all server scenarios
using the extracted component and runtime. Only successfully tested ZIPs are uploaded.
Documentation checks also compare all native/callback declarations with the extracted
include, resolve relative Markdown targets/headings, and verify the example/SQL catalogue.
The example compiler discovers all thirteen `.pwn` files. The four unattended tutorials
and logging example run alongside the original six scenarios: eleven public examples.
The separate real Pawn measurement fixture is not installed as a public example.
Interactive account/custom gameplay behavior requires separate player/provider validation;
the account mode compiles with authentication disabled unless its external provider is
installed and explicitly enabled.
Logs are retained even when a test fails; a failed package is not a release artifact.
A final job downloads both uploaded artifacts and repeats checksum, inventory, architecture
and extraction verification. It reuses the x86 build/test jobs without adding another build matrix.

For a local Windows run, pass `--platform windows`, `--build build-msvc32`,
`--libpq C:/deps/pg32/bin/libpq.dll`, `--runtime-dir C:/msys64/mingw32/bin`,
`--postgres-license C:/deps/postgresql-source/COPYRIGHT`,
`--openssl-license C:/msys64/mingw32/share/licenses/openssl/LICENSE`,
`--pthread-license C:/msys64/mingw32/share/licenses/libwinpthread/COPYING`, and
`--objdump C:/msys64/mingw32/bin/objdump.exe`. Linux uses `--platform linux`, the x86
build, `--libpq /path/to/libpq.so.5` and the PostgreSQL `COPYRIGHT`; `readelf` and `ldd`
must be available. Both accept `--output DIRECTORY` and verification accepts
`--archive NAME.zip --destination NEW_DIRECTORY`.

The final download job also assembles a source ZIP from Git's tracked source export,
both distributions, release notes, complete dependency manifests and `SHA256SUMS`.
Source export honors `.gitattributes`: `/audit/ export-ignore` keeps the preserved internal
audit records in Git without adding them to source ZIPs. Binary installation does not
stage `audit/`, and the package payload allowlist remains unchanged.
It uploads these as `omp-postgresql-release-FULL_COMMIT`. This is unsigned content
provenance; it does not create a tag or Release, grant publication permission, or
turn a branch/preview build into an integrated candidate. See [release gates](releasing.md).

## Pre-stable cleanup

Use `pg_prepare_file(connection, filename, parameters, prepared, section)` for named SQL.
`pg_prepare_section` was removed before RC.1. Programs using that older API require
source migration and AMX recompilation; RC.1 users have no new signature migration
for RC.2. Other leading argument/default positions remain supported. See [migration](prestable-cleanup.md)
and [internal diagnostics](debugging.md).
